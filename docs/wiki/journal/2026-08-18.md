# 2026-08-18

## Objectives
Diagnose and fix issue where logging usage and rolling back usage entries did not update stash quantities on Ravelry API or main page view.

## Working Directory Changes
- `src/stashstats/client.py`: Added `pack_id` parameter to `update_stash_item` to target specific primary pack records.
- `src/stashstats/models/history.py`: Enhanced `StashHistoryEntry` with optional `timestamp`, `id`, `date`, `yards`, `grams` to prevent validation errors.
- `src/stashstats/models/stash.py`: Added optional `skeins`, `total_yards`, `total_grams`, `total_meters`, and `notes` to `StashItem`.
- `src/stashstats/web/components/modal.py`: Updated `apply_usage_to_stash` and `rollback_usage_from_stash` to sync `primary_pack` and `packs` dicts; updated `create_usage_history_table` to support timestamp fallbacks.
- `src/stashstats/web/callbacks/modal.py`: Added `client.update_stash_item` API calls to `handle_save_modal` (Log Usage tab) and `handle_history_rollback`.
- `src/stashstats/web/components/stash.py`: Updated `group_stash_items` and `create_stash_item_row` to read `item.skeins` directly if present.
- `tests/web/test_modal.py`: Added unit tests verifying API calls on modal save and rollback.

## Decisions
- When logging usage or rolling back history in the modal, we must perform dual-write: update the Ravelry `StashItem` record (quantities, status, notes) via `POST /people/{username}/stash/{id}.json` AND update the timeline ledger via `app_data`.
- Keep `primary_pack` and top-level `skeins` in sync across local state dicts so that UI aggregations and row renders reflect immediately.

## Discoveries
- Ravelry stash updates require sending pack allocations via `payload["pack"] = {"id": pack_id, "skeins": skeins, ...}`.
- `GET /yarns/{id}.json?include=colorways` returns `colorways` array at the top-level response envelope, not inside `yarn`.
- Community colorway records frequently have empty string names `""` with manufacturer dye codes `code: "405"`. Models must be permissive and fallback gracefully rather than raising validation errors.
- `GET /people/{username}/stash/list.json` omits `packs`, `notes`, and `photos` lists (only present in detail endpoint); `primary_pack` contains the active inventory metrics.
- Pydantic `@model_validator` on `StashItem` and `YarnDetailResponse` automatically handles schema variations at the API boundary, guaranteeing consistent normalized attributes for downstream UI components.
